## 3. Gotchas

- **Run `npm run typecheck`, not bare `tsc`.** The `*.png` imports get their types from `next-env.d.ts`, which `next typegen` (or `dev` / `build`) generates and git ignores.
- **There is no development user any more.** Run the backend (`npm run start:dev`) with a migrated database and a seeded administrator, then sign in. With the backend down every page redirects to `/login`.
- **`proxy.ts` only checks that the session cookie exists** (`awtomatig.session_token`, or `__Secure-awtomatig.session_token` over HTTPS). A stale cookie passes it and is rejected by `requireSession()`.
- **Use `router.replace` + `router.refresh()` after sign-in and sign-out**, not `window.location` (the lint rule forbids it; dynamic pages are not cached client-side).
- **`/?demo=1` is development-only.** `getDashboard` and the page both refuse it elsewhere, and the page shows a "Sample data" badge.
- **Prettier reorders Tailwind classes** (the plugin). Run `npm run format` before `npm run lint`; do not hand-edit class order.
- **Recharts renders after the first measure**, so a screenshot taken too early shows an empty chart card. Wait or use `--virtual-time-budget`.
- **TanStack Table is on v8.** The latest tag (v9) is a different, store-based API.
- **`tanstack/react-table` trips React Compiler's `incompatible-library` lint rule.** The single `eslint-disable` in `DataTable.tsx` is intentional and explained there.
- **`next dev` writes `AGENTS.md`** (the Next.js notice block). Leave it; the file ends with a pointer to the root docs.
- **The website's `Button` lift and glow are not in the admin's `Button`** on purpose (DESIGN.md section 1.1).
- **`useFieldArray` owns a field called `id`.** React Hook Form puts its own key in `id` on every array row, so a question's database id is kept as `questionId` in the form and turned back into `id` when the request is built (`lib/recruitment/job-form.ts`).
- **Open the resume tab inside the click.** `window.open` after an `await` is blocked as a pop-up, so `ResumeButton` opens `about:blank` first, asks the backend for the link, then points the tab at it (and cuts `opener` off). Without a real user click the browser blocks it and the button says so.
- **`Dialog` is the browser's own `<dialog>`** (`showModal`): focus trap, Esc and focus return come from the platform. Esc and focus return were checked with real key and mouse events.
- **Money stays a string in the opening form.** The salary inputs are text, validated by pattern, and sent as `null` when empty; the only number conversion is comparing the two for the "maximum below minimum" message.
- **The client checks are for feedback only.** The backend repeats them; its field messages (`details`, as a list or an object) are put next to the field by `apiFieldErrors`, and anything without a field shows under the buttons.
- **The `/api` proxy address is baked in at build time.** `next.config.ts` reads `API_URL` when `next build` runs, so a build made for a local check picks up whatever `admin/.env` says (or the shell's `API_URL`), and `next start` then proxies sign-in to that backend. Set `API_URL` for the build when pointing at a scratch backend, and rebuild afterwards. A wrong target shows up as "This request was blocked" on the sign-in screen (the backend rejects the origin).
- **Checking UI in a script:** `innerText` returns the CSS-uppercased button labels (use `textContent`), JavaScript `el.click()` does not focus the element or count as a user gesture (use `Input.dispatchMouseEvent` for pop-ups and focus), and a DOM element cannot be returned by value from `Runtime.evaluate` (wrap it in `Boolean(...)`).
