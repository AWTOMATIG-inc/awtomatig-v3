## 2. Key decisions (and why)

| # | Decision | Why |
| --- | --- | --- |
| D1 | **Tailwind's default colors, radii and shadows are disabled** (`--color-*: initial`, etc.) | Makes it impossible to use off-system values by accident. Only design tokens exist. |
| D2 | **Spacing unit = 1px** (`--spacing: 1px`), so `p-16` = 16px | Utilities read directly in Figma pixels. ⚠️ `p-4` is 4px here, not 16px. |
| D3 | **Text styles are `type-*` utilities** (e.g. `type-heading-40`) that set family, size, line height, tracking and weight together | One class per Figma text style keeps typography consistent. Display and large headings scale with `clamp()`. |
| D4 | **Fonts:** Inter Tight for display and headings, Inter for body and labels, both through `next/font` | Taken from the Figma typography spec. Self-hosted, with no layout shift. |
| D5 | **Max container width 1440px** (the Figma frame); content only, **backgrounds stay full-bleed** | Requested so content never stretches on ultra-wide screens while backgrounds still reach the edges. |
| D6 | **The `--u` frame scale is capped at 1px** | The header and hero use `calc(var(--u) * N)` to scale Figma px with the viewport. The cap stops growth past 1440px, matching the container. |
| D7 | **One pair of site edges = the navbar pill's outer edges** (`--site-edge-start` / `-end`: 16px mobile, 49 / 60 frame px desktop), used by every `site-container`. Text is never padded differently; only break-out elements (the service panel) override `--gutter-*`. | Requested 2026-10-01: content must line up with the navbar edge. Before, the navbar (49/60), hero (72/60) and cards (60, 24 mobile) each had their own gutters, copied from separate Figma frames, so nothing aligned. The user chose "all text on the pill edge, panel keeps its bleed". |
| D8 | **One `<Button>` component** with variants `primary`, `glass`, `tint`, `dark`, `light`, `outline` and sizes `md` (40px), `lg` (54px; 50px on mobile), `xl` (56px, radius/12; footer CTA stack) and `nav` (navbar CTA) | Five unique button types were found across the Figma screenshots, and `tint` was added later for the navbar CTA. The variant is chosen by the surface the button sits on. |
| D9 | **Folder structure:** `ui/` (primitives), `icons/`, `layout/` (site chrome), `sections/<page>/<section>/` | Keeps reusable parts separate from page-specific ones, so it's always clear where a file goes. |
| D10 | **Effect CSS is colocated** (`hero.css` next to `HeroSection.tsx`) and `@import`ed from `globals.css` | One CSS bundle keeps the Tailwind layer order (theme → base → components → utilities). Next.js recommends against scattering global CSS imports. Since D23, only effects have CSS files. |

## 3. Gotchas

- **Next.js 16 is newer than most training data.** Read `node_modules/next/dist/docs/` before using an API. `next dev` rewrites the block at the top of AGENTS.md; leave it alone.
- **Spacing is 1px-based** (D2). Copying Tailwind snippets from elsewhere will produce tiny spacing.
- **Classes like `text-slate-400` or `rounded-lg` silently produce nothing** (D1). Use tokens.
- **`npm run lint` fails on a new `.css` file** under `app/components` unless it is in the `EFFECT_CSS` allowlist of `scripts/check-tokens.mjs`. That's deliberate (D25): put static styles in Tailwind or a `@utility` in `globals.css`.
- **New effect CSS must be registered** with an `@import` at the top of `app/globals.css` (`layout/` first, then `sections/`), or it won't load.
- **Don't put `site-container` on an element that has a background**; wrap the content inside it instead.
- **Inside the header and hero (from `lg` up), `<Button>`, the fixed `type-*` styles and every Tailwind spacing utility scale with `--u`** because those sections set `--spacing: var(--u)`. Outside them, 1 design px = 1px. Below `lg`, `--u` is unset in both sections.
- **Never put two Tailwind classes for the same property on one element** expecting the later one to win (e.g. `h-40` in Button plus `h-36` from `className`). The winner depends on Tailwind's stylesheet order, not class order. Add a variant or size instead.
- **`scale-*` takes whole percentages only** (`scale-98`, not `scale-98.5`); a fractional value silently generates nothing. Spacing utilities do accept `.5` steps (`h-1.5`, `translate-y-5.5`).
- **Effect CSS is mobile-first** with `@variant lg { … }`. VS Code's built-in CSS linter flags `@variant`, `@apply`, `@theme` and `@utility` as unknown at-rules; that warning is harmless.
- **`next/image` with a non-square PNG:** size it with one dimension plus `h-auto` (e.g. `w-16 h-auto`). `size-*` squashes it.
- **Header CTA on very narrow phones (<360px):** the label is visually hidden but still read by screen readers. Don't switch it to `display: none`.
- **Local visual checks:** headless Chrome won't render narrower than ~500px, so use an `<iframe width=390>` page for mobile. Don't pass `--virtual-time-budget`, because the hero canvas animation makes it hang. Python is not installed on the dev machine.
- **The header finds a page's hero by `[data-hero]`, not the `.hero` class** (D49): the `.hero` class is reserved for the frame-scale CSS only. A new hero needs `data-hero` on its section (`LinesBackground` takes it as a prop; a plain `<section>` sets it directly) or the hide-on-scroll header won't know where the hero ends.
- **The CSP in `next.config.ts` only applies in production** (`next start` or a real deploy); `next dev` has no CSP, since React's dev error overlay needs `'unsafe-eval'`. Check it with `next build && next start -- -p <free port>` if 3000 is already taken by a dev server — never kill a port you didn't start.
